# Design references: Victory Church room booking

This is the reference board for redesigning the internal room-booking app. Every URL below was checked on 2026-10-06: it returned HTTP 200 and the page title matched (method notes at the end). Each component gets one or two real references. Take the pattern from them, not the look.

## 1. Visual direction

**Feel.** It should read like a printed church bulletin or a calm editorial magazine that also happens to let you book rooms. Posters and room photos carry the color. The interface itself stays quiet: warm paper, dark ink, and Victory blue only where a person needs to act.

**Avoid.** Card grids everywhere, pill overload, gradients, glassmorphism, KPI tiles and fake charts, all-caps headings, heavy drop shadows, and tinted icon bubbles.

### Palette roles

| Token | Hex | Role |
|---|---|---|
| canvas | `#faf8f4` | Page background (warm off-white). The default "paper". |
| surface | `#ffffff` | Only for things that need to lift off the page: forms, dialogs, sticky booking panel, popovers. |
| ink | `#16181d` | Body text, headings, icons. |
| ink-muted (suggested) | `#5b5f68` | Meta lines, helper text, timestamps. |
| hairline (suggested) | `#e7e2d9` | 1px dividers, input borders, table rules. |
| fill-quiet (suggested) | `#efebe4` | Skeletons, disabled slots, hover rows. |
| victory-blue | `#02458d` | Primary buttons, links, selected date/time, active nav rule, focus ring. |
| victory-deep | `#012449` | Display headings on light, footer band, poster overlays. Use it rarely. |
| orange accent | `#f0994e` | At most one moment per screen: the VOTD quote mark, the "today" dot, a "new" marker. Never a button. |
| status (suggested) | green `#2f6b4f`, amber `#9a6a12`, red `#a23b2a` | Small status dots and the error-summary rule only. Never fills. |

### Type pairing

- **Nunito Sans** does all the UI work: navigation, labels, forms, tables, buttons. Weights 400, 600 and 700. Use tabular numerals for times and dates.
- **Newsreader** (editorial serif) is the voice: scripture, page-level display headlines ("This week at Victory"), the day numbers in booking lists, and the one-line empty and pending messages. Use it at optical sizes 28px and up, with italic for scripture. Never use it on controls.
- Suggested scale: 13 / 15 / 17 (body) / 22 / 28 / 40 / 56 (display). Body line height 1.55, display 1.1. Use sentence case everywhere.

### Principles

1. **Canvas before containers.** Separate content with space and 1px hairlines first. Use a white surface only when an element truly sits above the page.
2. **Image leads.** Posters and room photos are the color and the hierarchy. Chrome stays neutral so they can carry the page.
3. **Two voices, clear jobs.** Nunito Sans *does* things. Newsreader *says* things. Don't swap them.
4. **Blue means "you can act here".** Use it for primary actions, links, selection and focus. Orange is a highlight, used at most once per view.
5. **Status is language.** Show a text label with a small dot ("Pending review", "Approved", "Denied: room in use"), not colored pills. Reasons stay visible.
6. **One primary action per view.** Everything else is a secondary button or a text button.
7. **Calm motion.** Use 150–200ms ease-out fades and ≤8px slides, for state changes only. Honor `prefers-reduced-motion`.
8. **Plain words, no dead ends.** Every pending, empty or error state says what happened and what to do next.

## 3. Implementation notes

- Dividers are 1px `#e7e2d9`. Section breaks get 48–72px of space, with a rule only where the content changes.
- Radii: 6px for inputs and buttons, 10px for dialogs and sheets, 0px for photos in the editorial grid (2px is the most you can get away with).
- Shadows only on floating layers (dialogs, popovers, the mobile sheet): one soft `0 8px 24px rgb(22 24 29 / 0.08)`.
- Focus: 2px Victory-blue outline with a 2px offset on every interactive element, including map polygons and calendar cells.
- Imagery: posters keep their own art. Room photos are shot in daylight with consistent 4:3 crops and get no colored overlays. Demo assets live in `public/demo/`, brand assets in `public/brand/`.

## Verification notes

- Method: each URL was requested with a browser user agent on 2026-10-06 and returned HTTP 200 with a matching page title. Text content was spot-checked for Linear Triage (accept/decline with comment), Linear Members (status filters, suspend), Robin Wayfinding (office maps), Vercel Accounts (login methods and connections), Cal.com Google Calendar, and Bible.com Verse of the Day.
- `linear.app/login` and the Mobbin pages render on the client. The URLs resolve, but most Mobbin screenshots need a free sign-in to browse.
- The Airbnb listing is a live third-party listing and may disappear. If it does, open any listing from the Manila search link.

## 4. Where the build differs from the references

- **Account approve/restore** open a short confirmation dialog instead of running right away with an Undo snackbar. Each decision sends a GHL email immediately, so an Undo would arrive after the email had already gone out.
- **Announcement editor** keeps a single 4:5 poster upload with a preview. Crop variants, summary/link fields and the live bulletin preview were left out because posters are designed outside the app. The newest live poster is featured automatically.
- **Status** is shown everywhere as a coloured dot plus text (`StatusMark`), never as pills, matching Primer's state labels without the filled capsule.
- **Room photos** fall back to a typographic placeholder (the room letter set in Newsreader) until real photos are uploaded to `rooms/`. No stock or generated imagery is used.
- **Admin tables** are hairline grid lists that stack into rows below `lg`, so nothing scrolls sideways on phones. The only horizontal scroll is the room timeline, which is a scale.
